UI State Lab

A production-facing design-state matrix for empty, loading, resolving, disabled, resolved and error conditions. Presentation only: gameplay authority stays in the runtime.

Event / choice

Resolving

Decision being recorded

Primary controls stay visible but cannot be submitted twice. Feedback explains what is happening without exposing future consequences.

Event / data

Loading

Loading event

The hierarchy remains stable while content loads. No layout jump is required for the narrative surface.

Event / availability

Blocked

Unavailable

The reason is explicit and actionable. Disabled state is not communicated by color alone.

Event / completion

Resolved

Resolved

The result is presented as a recorded outcome. The screen does not rewrite history or fabricate future effects.

History

Empty state

No entries yet

A calm explanation replaces a blank surface. The user can understand why the section is empty.

Investigation

Uncertain evidence

Uncertain

Uncertainty is preserved as a semantic state. The UI never upgrades an observation into a verified fact.

Runtime boundary

Error recovery

Could not load

The error explains the next safe action. It does not imply a gameplay transition or silently mutate state.

Accessibility

Large text

Readable

Controls and state labels remain understandable when text size increases. Layout is allowed to grow rather than clip.
